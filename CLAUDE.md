# Project conventions
- UI copy is Turkish; code, identifiers and comments are English. Route segments are Turkish (`/bugun`, `/danisanlar`).
- Server data access goes through `withTrainer()` in `src/db/index.ts` (RLS applies). Use `adminDb` only for signed-out paths and filter by an id you resolved yourself.
- Inside `withTrainer`, run queries sequentially — a transaction holds one connection.
- Schema changes: edit `src/db/schema.ts`, run `pnpm db:generate`, then `pnpm test:db`. Views/triggers live in custom migrations.
- Package balances come from the `client_package_balances` view; never store a separate remaining-count.

## UI / design system

- Visual direction (user's reference: merkezim.com): light-grey canvas (`bg-canvas`), white `surface` panels (rounded-2xl, hairline border, `shadow-card`), Poppins everywhere with tight semibold headings, pill buttons in ink (lime in dark mode), and a lime accent (`bg-lime text-lime-foreground`, always ink text on lime) used sparingly: the current tab, the one stat that needs attention, "now" markers. Lists are rows inside one `divide-y overflow-hidden surface`; people get `<Avatar>`; summary numbers use `<StatTile>`. Avoid bare bordered boxes on white and small grey section labels. `.claude/skills/design-system/SKILL.md` (typeui Clean) still applies for accessibility, spacing and scale.
- Use the semantic tokens from `src/app/globals.css` (`primary`, `lime`, `success`, `warning`, `destructive`, `muted-foreground`, …), never raw Tailwind palette colours.
- WCAG AA: the base `success` / `warning` / `destructive` colours are for fills, icons and borders; text in those colours uses the `-strong` variants (`text-success-strong` etc.).
- Type scale 12/14/16/20/24/32 (`text-xs` … `text-3xl`), 8pt spacing, 44px touch targets on mobile (controls shrink at `md:`).
- Every route under `src/app/(app)` has a `loading.tsx` built from `src/components/skeletons.tsx`, so tab switches show the new page's frame at once. Add one when adding a route.
- Buttons that start a server action use `loading={pending}` (spinner + disabled); plain `<form action>` forms use `SubmitButton`. Only the clicked button spins.
- Package prices: `price` is cash, `installmentPrice` + `installments` the optional plan, `compareAtPrice` the struck-through price. Read them through `src/lib/pricing.ts`.
- Group classes (`src/db/groups.ts`): occurrences are lessons generated `GROUP_HORIZON_DAYS` ahead by `ensureGroupOccurrences` (called by the calendar, Bugün, group pages and the portal) and keyed by `(group_class_id, occurrence_date)`. A place is held by attendance `scheduled`/`attended`/`no_show`. Group lessons only draw on group packages (`pickPackage(..., { strict: true })`).
- In raw `sql` subqueries on a single-table select, write the outer column as `"table"."column"`; Drizzle leaves `${table.column}` unqualified there.
- Product name is `APP_NAME` ("Stüdyom", domain `APP_DOMAIN` "studyomapp.com") from `src/lib/config.ts`; never hard-code it. Marketing copy (landing, SEO) addresses trainers with "siz"; the app and client portal use "sen". Packages are "seans paketi" in marketing, lessons are "ders".
- SEO: `src/app/robots.ts` (app, portal and sign-up routes disallowed), `src/app/sitemap.ts` (landing, KVKK, published trainer pages), `src/app/opengraph-image.tsx`, JSON-LD on the landing (SoftwareApplication + FAQPage, no ratings) and on trainer pages (SportsActivityLocation). Set `NEXT_PUBLIC_SITE_URL` in production so canonical/OG URLs are absolute.
- Engagement (`src/db/engagement.ts`): "Geliyorum" sets `lesson_attendees.confirmed_at`; the cron (`GET /api/cron`, Bearer `CRON_SECRET`, every 15 min) sends reminders, renewal offers and the Monday summary. Every job marks its rows (`reminder_sent_at`, `renewal_offered_at`, `trainers.weekly_summary_week`), so runs stay idempotent.
- Reminders are push only and go `trainers.reminder_hours` before a lesson (the trainer can turn them and renewal offers off in Ayarlar → Hatırlatma ve mesajlar); the answer buttons sit at the top of the client's page (`#yaklasan`). Every ready-made text (reminder, renewal, the drafts behind message/WhatsApp buttons) comes from `renderTemplate()` in `src/lib/templates.ts`, with the trainer's overrides in `trainers.message_templates`; never hard-code client-facing copy for these.
- Reaching a client from a list row: `<ContactButtons>` (`src/components/contact-buttons.tsx`) — in-app message first (`/mesajlar/<id>?taslak=…` prefills the box), WhatsApp second with `<WhatsAppIcon>`. Use the WhatsApp icon only on buttons that open WhatsApp.
- Notifications go through `notifyTrainer(trainerId, kind, msg)` / `notifyClient(target, kind, msg)` in `src/lib/notify.ts`; the recipient's `notify_prefs` (kinds and defaults in `src/lib/notify-prefs.ts`) decide push and/or e-mail. Don't call `sendMail` for app events — only for mails that must always arrive (the client's personal link after sign-up or approval). Messages never go by e-mail. Web push: `src/lib/push.ts` + `public/sw.js`; a subscription with `client_id` null is a trainer device.
- Manifests are route handlers (`src/app/manifest.webmanifest`, `src/app/p/[token]/manifest.webmanifest`), not `manifest.ts`: file-based metadata would override the per-client manifest that makes "Ana ekrana ekle" open the client's own page.
- Trial packages (`package_templates.is_trial`) are once per person: `requestPackage` and `recordSignup` refuse anyone with a package or a previous application; they are never offered for renewal.
- Progress (`src/db/progress.ts`, `src/lib/measurements.ts`): client notes (`client_notes`, optional `lesson_id`, `visible_to_client`), measurements (one value per client/metric/day; `metric` is a built-in key or a `measurement_types` id). Measurements are health data: `saveMeasurements` refuses without a `health_data` consent. Charts are `<ProgressView>` / `<ProgressChart>` in `src/components/progress-chart.tsx` (plain SVG, no chart library).
- The client page (`/p/<token>`) is tabbed (`portal-tabs.tsx`, the hash picks the tab: `#dersler`, `#ilerleme`, `#mesajlar`, `#bildirimler`; section anchors like `#paketler` open their tab). The trainer's client page uses `?sekme=` (genel / notlar / olcumler).
- Programs (`src/db/programs.ts`, `src/lib/programs.ts`): `programs.kind` workout | nutrition; `client_id` null = template, a client's program is a copy (`copyProgram`). The client sees only sent (`sent_at`), non-archived programs; the newest sent one per kind is current. Days/items are rewritten on save; check-ins survive by day title. Exercise library is seeded once (`ensureExerciseLibrary`). Nutrition plans may carry one PDF (`program_attachments`, ≤1.5 MB, served by `/programlar/[id]/pdf` and `/p/[token]/beslenme-pdf`). Nutrition copy says "beslenme önerisi", never "diyet listesi", and always shows `NUTRITION_DISCLAIMER`.
- Periodic measurements: `clients.measure_every_days`; due clients show on Bugün (`dueMeasurements`) and get one push per interval from the cron (`measureRemindersDue`, 10–20h local).
- Support (`src/db/support.ts`): `support_threads` / `support_messages`. Landing contact form → a thread with no trainer, answered from /yonetim by e-mail; a trainer has one ongoing thread (Ayarlar → Bize yazın), answered in the app with a push. Contact-form messages e-mail the team (`SUPPORT_EMAIL`, `mailTeamAboutContact`); messages from the app are not e-mailed, they wait in /yonetim/mesajlar. RLS scopes rows by `trainer_id` (null for landing rows, so only the owner connection sees them).
